## What was built
1. **Oreshards, the premium currency** (20261106000007_oreshards.sql): `oreshard_wallets`, the append-only `oreshard_ledger`, `purchases` (one row per Checkout Session, session id unique), `stripe_events` (every handled Stripe event id). Settings `oreshard_bundles` (admin-editable: Pouch $1.99 = 200, Sack $4.99 = 550 (+10%), Chest $9.99 = 1,200 (+20%), Hoard $19.99 = 2,600 (+30%); Stripe's 50-cent minimum enforced) and `oreshards_enabled` (the switch). One-way conversion `oreshards_to_coins`: 1 Oreshard = 1 Coin, never back, refused while a balance is below zero.
2. **Who may buy** (`oreshard_checkout_start`): signed in, not banned, the agreement accepted, the shop on, a real bundle; an **under-13 account needs an approved parent** (consent_status approved), else the page shows "A parent must approve this account before it can buy anything."
3. **`stripe-checkout` function:** the player's JWT, the database's checks, one Stripe customer per player (kept on the profile), then a Stripe-hosted Checkout Session (price_data from the settings, dynamic payment methods, `integration_identifier` oreheart-oreshards-xxxxxxxx, metadata with the purchase id, success/cancel URLs only on the game's own origins), API 2026-10-28.endive, StripeClient instance. The session id is stored on the purchase.
4. **`stripe-webhook` function** (no JWT; the Stripe signature is the proof, SubtleCrypto; live-mode events are refused): `checkout.session.completed` and `checkout.session.async_payment_succeeded` credit ONLY when `payment_status` is `paid`, exactly once per session (idem key = the session id; the paid amount must match the purchase); `async_payment_failed` closes the purchase; `charge.refunded` and `charge.dispute.created` take the Oreshards back (the balance may go below zero, money spent comes down, the account gets a `payment_review` flag for Ken). Every event id is recorded first, so a repeated delivery is skipped; if a handler fails the id is forgotten so Stripe's retry is handled.
5. **The game:** a "Buy Oreshards" screen (four painted chests, the bonus lines, "Oreshards are not refundable and have no cash value", the balance, the one-way convert box with its warning, the purchases list) reached from the Shop's new Oreshard counter and its "+". Back from Stripe the screen re-reads the balance for a while; the browser never credits anything. Test page `?test=1&econ=oreshards` (`&kid=1` = an under-13 without a parent).
6. **Admin player page:** Oreshards, the purchases with their Stripe session and payment ids, the review flag; money spent was already there and now follows the purchases (`admin_oreshards`, `admin_player_detail`).
